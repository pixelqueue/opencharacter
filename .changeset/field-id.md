`fieldId(pattern, key, …)` gives the qualified ID of the field a family pattern names for a key, in the pack that added the key, so a core change, effect or `{ formula }` field target built from a family key reaches the field an add-on declared for its own key. Formulas evaluated over input fields (activation conditions, state defaults, template values) now read `fieldOf` from the adding pack too.
